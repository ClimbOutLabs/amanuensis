Aman can use a different model for each job: one to answer you, and others for background work such as summarizing long chats. This page explains each job, how to set it, and how to see which model did what.

How to get there: Click **More** in the left bar, then **Settings**, then **Roles and Personas**.

Two Settings pages work together:

- **Settings → Models** connects model providers and lists the models you can use.
- **Settings → Roles and Personas** decides which of those models does which job. It has two tabs: **Roles**, for the job assignments below, and **Personas**, for the named personas.

## The jobs

| Job                         | What it does                                                         | When you leave it empty   |
| --------------------------- | -------------------------------------------------------------------- | ------------------------- |
| **Main chat model**         | Answers you directly (`model` on the agent spec).                     | You need to choose one.   |
| **Coding / subagent model** | Runs the helper tasks Aman hands off (`auxiliary_models.delegation`). | Uses the main chat model. |
| **Compaction model**        | Summarizes older parts of a long chat (`auxiliary_models.compaction`). | Uses the main chat model. |
| **Helper model**            | Does the background work after each chat. It picks out what to remember, files it on your pages, tidies the pages and names the chat. | Uses the main chat model. |

- A job left empty follows the main chat model at the moment it runs. So when you change the main chat model, every job left empty changes with it.
- Clearing a job removes its own choice. It does not copy today's main chat model into it.
- A helper task that asks for a specific model still gets that model. Your default never overrides a deliberate request.
- A poor compaction or helper model hurts later answers and memories, so choose one you trust.
- The helper model is one choice for all of Aman. It is kept on the computer Aman runs on, so it is the same in every browser. The daily tidy-up follows it too. A smaller, faster model works well here.
- If you later remove the helper model under **Models**, the background work goes back to the main chat model. Settings then shows a note under the choice.
- An agent that names its own summarization model (`auxiliary_models.summarization`) keeps that model for its chats.

!!! note "Short background checks"

    To decide whether you asked to switch personas, Aman can make one short call to the main chat model, with no tools. It is not a separate job. The call only decides whether you asked to change who answers. It can't answer your message or pick a model you haven't set up.

!!! note "Noticing"

    Noticing makes one short, tool-free call when it finds something new for you, such as a calendar clash or a bill due soon. The call goes to the model a new chat starts on. It only suggests how loudly to tell you, and your [Reach me](../packages/trueforge/guide/topics/reach-me.md) settings decide. It is not part of a chat, so it shows in no chat's details, but it counts toward the daily Token Factory cap. Nothing is called when nothing new is found.

### If a chosen model goes away

If a job names a model that is no longer set up, the turn stops and says so. Aman never quietly hands the work to a different model, because work credited to a model that didn't do it is worse than a clear error.

## Seeing what each model did

### The line under each answer

Turn on **Agent details** in the chat. Each answer's details then start with a quiet line. It names the model that answered, its provider, and the tokens and cost of the whole turn, with any helper calls added in:

```text
Nemotron 3 Super · Token Factory · 2,140 tokens (1,800 in, 340 out) · $0.0011 at list price · + 2 helper calls on Nemotron 3 Super
```

### Every job that ran

With **Agent details** on, each job that ran is listed with its model, calls, tokens and cost. The jobs are the answer, helper tasks, compaction, turn summarization, profile learning and the library relevance check.

Token counts are what the provider reported for each call. A call whose provider reported nothing shows `usage not reported`, never zero or a guess.

Compaction that uses the main chat model is counted with the chat calls. Choose a separate compaction model to see it on its own row.

### Cost

Cost is an estimate from a price table, in US dollars per million tokens. It says "at list price" because it is not your bill.

- Token Factory models have built-in list prices, read on 2026-10-15.
- Set `TOKEN_FACTORY_PRICES` to change those prices or to price a model from another provider.
- A model with no price shows tokens only.
- **Settings → Models** shows today's tokens and cost for each Token Factory model, and how much of the daily limit is left.

To hide the line and the helper rows, go to **Settings → Appearance** and, under **Answers**, turn off **Show model and cost in answer details**. Usage is still counted.

## Personas

A persona is a name, a short role and a model, set under **Settings → Roles and Personas → Personas**. Its model is a real setting you can see and change, not something hidden in its instructions. For making and using personas, see [Personas](../packages/trueforge/guide/topics/personas.md).

### Calling a persona

You can name a persona directly:

```text
Zara, what do you make of this?
ask Zara to look at the second page
let me talk to Zara
@Zara
Could Zara answer this one?
```

Addressing a persona directly, or starting with one of the common lead-ins above, switches at once, without a model call.

??? note "How other wording is checked"

    Other wording that mentions a persona gets one short check by the chat's main model. The check sees only the current message, the persona names and ids, and who is answering now. It gets no persona instructions, tools, files, attachments, memory or chat history.

    Aman only accepts a clear answer that names a real persona, with the exact request that goes with it. It turns down a shorter name that overlaps a longer persona name.

    An unclear, outdated or unsure answer keeps the current speaker. If you pick a persona in the app while the check is running, your pick wins.

    The check's model, finish reason and usage are recorded apart from the answer.

Nothing picks a persona from what a message is about. A name in ordinary writing ("I was reading about Zara yesterday"), a quote, a "what if", or "don't switch to Zara" switches nothing.

### Going back to the main assistant

Use the assistant's name from **Settings → Personalization**, such as "Can I talk to Mannie again?" Or say "default assistant" or "main assistant". The button beside the message box always works too.

### While a persona answers

- Follow-up messages keep going to that persona, in the same chat, with the same history.
- The chat shows who is answering and on which model, with one control to go back to the main assistant.
- Naming a different persona switches straight to it.
- The chat's own **Main chat model** never changes.
- Compaction keeps using the compaction job (or the chat's model). Summarizing the whole chat never follows a persona picked for a few turns.
- Tools, approvals, the workspace and the chat's limits stay the same. A persona changes who answers, not what Aman may do. Its role is one section of the instructions and can't override Aman's safety rules.

Names and other names must be unique across your personas. A duplicate is refused when you save it, because a message could then mean two personas.

If a persona's model is no longer set up, calling the persona fails with a clear message. The persona keeps its setting, so you can point it at another model instead of losing it.

## API

```text
GET    /api/v1/personas
POST   /api/v1/personas
PUT    /api/v1/personas/{persona_id}
DELETE /api/v1/personas/{persona_id}
GET    /api/v1/personas/{persona_id}/context
GET    /api/v1/sessions/{session_id}/persona
PUT    /api/v1/sessions/{session_id}/persona
GET    /api/v1/sessions/{session_id}/persona-activations
```

- `GET /api/v1/personas/{persona_id}/context` returns the exact text the model gets when that persona answers, so nothing about the persona is hidden.
- `persona-activations` lists, newest first, which persona answered this chat and why.
- Entries with a `turn_id` record that turn's history. They survive deleting the persona, so a past turn can still say which persona and model answered it.

An install with no personas works exactly as before: no persona is picked, nothing is recorded, and every turn uses the chat's own model.
