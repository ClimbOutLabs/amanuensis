Aman is meant to be installed with the installer (`installer/install.sh`, see [Install](/install)). This page says plainly what an installed Aman protects against, what it does not, and what to check before anyone else can reach it.

## What the installer sets up

Each instance is one person's Aman, with its own sign-in, data, secrets and ports.

- **Sign-in is always on.** Every instance runs Aman's own sign-in service, with one owner account: the email you gave the installer. The app refuses to start without it, and only that one verified email can sign in. Your password is never stored; the installer keeps only its hash.
- **Your home network, over https.** By default the app answers at this computer's private addresses (its LAN and Tailscale addresses, `localhost` and its host names) over https, with a certificate from an authority the installer makes on this computer. The plain port only sends devices to https and serves the `/trust` page. `--local-only` keeps the app on `127.0.0.1` alone. `--tls off` turns https off, and then the password crosses the network unencrypted, so use it only with Tailscale.
- **Cloud servers start closed.** On a server at a common cloud provider, a new instance opens on `127.0.0.1` alone, because private addresses there are shared with other customers. `--home-network` overrides that.
- **The internet only over https.** A public address is never served over plain http. For access from the internet, use `--public-url`, `--login-url` and `--tls caddy`, open only TCP 443 (plus SSH from your own address), and see [Https with Caddy](/install#https-with-caddy).
- **Docker 28 or newer on Linux.** Older Docker Engines let other devices on your network reach ports meant for this computer only, so the installer and `aman doctor` stop and say so.

`aman doctor` checks all of this again at any time.

## Running from source, Docker Compose or Kubernetes

The other ways to run it in [Quickstart](/quickstart) set up sign-in differently.

- `pnpm standalone:dev` runs standalone mode, with the same rules as an installed instance: it refuses to start without `OIDC_ISSUER_URL`, `OIDC_CLIENT_ID` and `OIDC_CLIENT_SECRET`, refuses an issuer that is not Aman's own sign-in service (path `/dex`), accepts an http issuer only on a loopback host, needs `OIDC_ALLOWED_EMAILS` to hold exactly one address, and accepts only verified emails. It also rejects requests whose `Host` is not a loopback name on the instance port or the `PUBLIC_BASE_URL` host (421) and cross-origin writes (403).
- Docker Compose (`docker-compose.yml`) and the Helm chart for Kubernetes (`charts/trueforge`) run hosted mode (`STANDALONE=false`) with Postgres and Redis. Without the three `OIDC_*` variables, every request is one shared admin identity, so anyone who can reach the app port can read chat history, change settings and use every configured model, connector and sandbox credential. Hosted mode refuses to listen on a non-loopback address without sign-in, unless `REQUIRE_AUTH=false` explicitly accepts the risk. Configure sign-in before anyone else can reach either one. The Compose file publishes port `8791` on `127.0.0.1` only and sets `REQUIRE_AUTH=false` for that local stack; never copy that into anything other people can reach. It also ships `POSTGRES_PASSWORD=trueforge` and binds Postgres (`5433`) and Redis (`6380`) to `127.0.0.1`; change the password before running it on a shared machine. Its `login` profile turns sign-in on: see [Turn on login](/quickstart#turn-on-login) and [Setup Login](/authentication/overview).
- On Kubernetes, turn sign-in on with the chart's `configs.oidc` values (`enabled`, `issuerUrl`, `clientId`, `clientSecret`); the chart's [README](https://github.com/ClimbOutLabs/amanuensis/blob/main/charts/trueforge/README.md) has the details.

## Prompt Guard screens

Aman can run recalled memories and live tool output past a classifier sidecar (`aman-content-screen`) that looks for prompt injection. Both screens are optional and off by default. The sidecar supports a CPU (default) and a GPU backend behind the same HTTP contract; see `ops/prompt-guard/README.md`.

- **Memory recall screen** (`MEMORY_SCREEN_ENABLED`, env default `false`): checks memories recalled from the memory bank before they reach the model. Turn it on per memory bank in **Settings → Memory**, using the "Screen recalled memories with Prompt Guard" switch under the active bank. The switch is disabled until a classifier URL (`MEMORY_SCREEN_URL`) is configured and reachable. Your own stated memories are never withheld by this screen; it applies to memories that came from tools, documents, or email.
- **Tool output screen** (`TOOL_OUTPUT_SCREEN_ENABLED`, env default `false`): checks tool results from structurally open-world tools before they re-enter model context. This one is environment-only; there is no Settings switch. It uses the same classifier URL, bearer token, and threshold as the memory recall screen (`MEMORY_SCREEN_URL`, `MEMORY_SCREEN_AUTH_TOKEN`, `MEMORY_SCREEN_THRESHOLD`).

Leaving both off does not remove the structural defenses described below, which are always on regardless of these settings.

## Structural defenses that are always on

Two defenses do not depend on the Prompt Guard screens and cannot be turned off:

- **Sandbox network policy**: every sandbox (local or Daytona) is restricted to a fixed outbound domain allowlist covering PyPI and GitHub hosts only. Everything else is denied by default, which also denies access to private networks and cloud metadata endpoints (for example `169.254.169.254`) from inside a sandbox.
- **HTML Spaces render without scripts**: a `format: 'html'` Space body renders in a sandboxed iframe with no `allow-scripts`, so nothing in the rendered HTML can execute. An allow-list sanitizer strips `<script>`, `<link>`, `<iframe>`, `<object>`, `<embed>`, `javascript:` URLs, and `@import` before the HTML reaches the iframe, as a second layer behind the sandbox attribute itself. Elements outside the allow-list lose their tag but keep their text, except scripts, frames, embedded documents and similar, which are removed with their contents.

## Supply chain: package release age

`pnpm-workspace.yaml` sets `minimumReleaseAge: 0` in this repository, meaning pnpm will install a package version the moment it is published, with no waiting period during which a malicious release could be caught and pulled. This is set to 0 so contributors and CI are not blocked on a newly published dependency bump. An operator building their own image or maintaining a long-lived deployment may want to raise this value (for example to a few days) in their own fork or override, trading immediate access to new releases for a window in which supply-chain attacks tend to get caught and yanked.

## Limits to keep in mind

- Sign-in protects the app, not the computer it runs on. Anyone with administrator rights or Docker access on that computer can read Aman's data, and backups are stored unencrypted.
- Tool approval and sandboxing reduce risk; they are not an unlimited safety boundary. Review enabled capabilities, provider trust, egress policy, and approval requests.
- Model credentials stay in the harness. Built-in MCP access from Code Mode is bridged back through the harness so its stored MCP tokens do not enter the sandbox; do not assume the same boundary for arbitrary custom code, tools, or integrations. Administrators remain responsible for secret storage, transport security, and provider configuration.
- Markdown memory stores memories as plain files under `MEMORY_MARKDOWN_DIR` (default `./data/memory`) — treat that directory as sensitive. Recall screening and live tool-output screening default off.
- The Prompt Guard sidecar under `ops/prompt-guard` is evaluation-only and is not an accepted production security control.

See [authentication](/authentication/overview), [sandboxing](/sandbox), and the [memory runbook](https://github.com/ClimbOutLabs/amanuensis/blob/main/ops/memory/RUNBOOK.md) before enabling those features outside local development.
