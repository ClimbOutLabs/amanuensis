`@truefoundry/trueforge-ui` provides a production-ready agent chat experience as a single, reusable React component. Aman ships this full chat UI with the server — browse agents, stream responses, approve tools, connect MCP OAuth, and manage Settings — and publishes the same experience as `@truefoundry/trueforge-ui` so you can embed it in your own React app.

Key Features:

- **Agent Modes** - Chat with a single agent, browse an agent library, or allow users to create and compose new agents.
- **Chat** - Supports streaming responses, session history, tool calls with approval workflows, and file attachments.
- **Themes** - Includes built-in themes (Paper, Forest, Midnight and High contrast), with support for creating custom themes.
- **Layouts** - Supports full-screen layouts with a sidebar or drawer, as well as embedded layouts with side-docked or floating widgets.
- **Integration Settings** - Configure models, MCP servers, skills, and sandbox environments.
- **Server Configuration** - Choose between Aman, a fully custom server, or TrueFoundry.

## Chat history and organization

The sidebar's chat history list supports renaming chats, filing them into folders, and controlling how much detail is shown per chat.

**Rename a chat**: open a chat's **···** menu (the desktop dropdown, or the sheet on mobile/compact layouts) and choose **Rename**. Type the new title and press Enter, or click **Rename**, to save; Escape cancels without saving, and an empty title is rejected. Renaming updates the sidebar row immediately and persists to the session.

**Chat titles**: a new chat is titled from the subject of its first exchange, in a few words, once the first reply finishes. While that first reply is being written, the chat carries the start of your first message as its title. A title you set by renaming is yours: Aman never replaces it. A scheduled run's chat is titled with its schedule's name and the day it ran, such as "Morning brief · Thursday, November 13".

**Folders**: click **New folder** next to the chat history header to create a folder. Move an existing chat into one from its **···** menu (**Move to folder**), which also lets you create a folder on the spot. Folders render as collapsible sections above the unfiled chats; each folder's own **···** button opens a dialog to rename or delete it, deleting a folder keeps its chats, just unfiled.

**Unseen answers**: a chat whose latest answer you have not opened yet shows a dot and a bold title in the list, the same mark a chat gets when a reminder lands in it. The mark clears when you open the chat. Aman stamps each chat with the time its latest answer landed, and your browser remembers when you last opened each chat, so the mark is kept per browser: reading a chat on your phone does not clear its mark on your laptop.

**Agent details**: while a chat is open, the **Agent details** switch in the header turns the agent's internal steps on or off for that chat. On a phone narrower than 360px it is labelled **Details**. The switch shows whether they are on. With them on, each answer shows its steps, tool calls, sub-agents, the lines the model wrote between steps, and the model and cost line. With them off, you see only your message, the answer, and anything that needs you: approval cards, notices written for you, and one progress line while Aman works. If a step failed or was blocked, one plain line under the answer says so. A reply that could not finish says so in one plain line. The switch only appears once the chat has a persisted session, and is hidden while the chat is idle or on a fresh, unsaved chat.

A chat's **···** menu itself only appears when at least one of Rename, Delete, or Move to folder is actually available for it.

**Incognito chats**: on a new chat, press **Start incognito chat** beside the persona button before you send the first message. Hover over the button for a short reminder of what it does. The message box then gets a frame in the text color instead of the accent color, and a line above it says that nothing from the chat is kept and whether the words leave this machine. Aman can still read its memories, spaces and reminders in an incognito chat, but saves nothing from it: it cannot make spaces, reminders, schedules or personas there, and the web browser is off. The line above the message box is checked again after each reply and when you switch persona. While the chat is open, it shows in the history list with an **Incognito** label, in that browser tab only. It never shows in search, and it cannot be moved to a folder. Press **Close and delete** above the message box, then **Delete for good** to confirm; the chat is deleted for good and the app opens a new chat. An incognito chat left open is deleted 24 hours after its last reply. See [Privacy](/privacy#incognito-chats) for what is kept on purpose.

## The right rail: the assistant's desk

The panel on the right is the assistant's desk: what it is holding for you, right now, in this context. It only ever reads records the app already keeps, so it is always current and it never starts a model turn, reads email, or costs anything to look at.

On Home it shows the day: your calendar events with the time you become free, today's reminders that have not gone off yet, and the actions waiting for your OK. When a reminder goes off it leaves the rail and shows under the **For you** bell instead. The **Reminders** page in the left panel stays the place to see every reminder and delete one. A calendar row opens the event's details where it sits; a reminder or an action opens the chat it belongs to, which is where the action is answered. Once every timed event on the day has finished, the list also shows the next morning's first event, marked as tomorrow's. When more actions are waiting than the list can show, the list says so. In a chat it shows what the assistant is using there: the memories recalled for your last message, the files attached to the chat, and that chat's waiting actions. The memories sit under **From memory**, which stays folded until you open it, and each one says where it came from and how long ago. The × on a memory takes it out of that chat for the rest of the chat only; your memory itself is not changed. **Delete** removes the memory everywhere, after it asks you once, and it cannot be brought back. A line that comes from one of your pages names the page and has no × or **Delete**, because it is changed on its page. **Manage memory** opens the memory settings, which is where memory is edited.

On a phone, or in a narrow window, the rail is a strip at the bottom. Open, it shows the assistant's name and the same lists under it, in a short area you can scroll. Folded, it shows only the assistant's picture.

## Approval cards

When Aman wants to do something that needs your OK, such as opening a page, typing into a form, running a command, adding a calendar event or sending an email, the chat shows an approval card. Every card has the same layout:

- A status line at the top. It says **Waiting for you** until you answer.
- A short question, such as "Send this email to Rui?".
- One quiet line on why Aman is checking with you, when there is a reason.
- A line on what follows from saying yes, when something does. For example: "Once this is sent, it can't be unsent."
- The facts, each shown once: the full address, who it goes to, an amount, or the exact command. A site the question already names is not listed again.
- One row of buttons, all with the same outlined look, so none is pushed on you. **Allow** always comes first, then **Always allow in this chat**, **Change it** and **Not now**. When the action cannot be undone or reaches other people, the last button uses safe words instead of **Not now**, such as **Don't send** or **Keep it**. On a phone the buttons share the row and wrap.
- **Details**, only when there is more to see, such as the full request a click or a form sends, or **Always allow everywhere**.

An email card also shows the message exactly as it will be sent, and keeps its buttons in view while you scroll a long message. A calendar card shows the whole event.

The card is set a little smaller than the chat, so it never shouts. The question is the one line at the chat's text size, in bold. Everything else is a size smaller, and the status line is the smallest. An email's message stays at the chat's text size, because it is the thing you are approving.

After you answer, the card shrinks to one line, such as "Allowed · 09:14" above the question. Actions a scheduled run held for you use the same card under **Needs your OK**.

## Spaces and folders

The **Spaces** page lists the pages Aman keeps up to date for you. You can file them into folders, the same way as chats.

**Folders**: click **New folder** at the top of the Spaces page to create a folder. Open a space, choose **Space actions**, then **Move to folder**, to file it. That dialog also lets you create a folder on the spot, and **No folder** takes the space back out. Folders show as collapsible sections above the spaces that have no folder. Each folder's own **···** button opens a dialog to rename or delete it. Deleting a folder keeps every space in it, just without a folder.

You can also ask Aman to file a space for you, for example "put my Pets space in a folder called Home". Aman uses an existing folder with that name or makes a new one, and can take a space out of a folder. Aman cannot rename or delete folders.

Moving a space is not a change to the space. Its version number and its updated time stay as they were, and going back to an earlier version keeps the space in its folder. Space folders are separate from chat folders.

## Images in chat

Chat shows pictures you upload, image attachments on email Aman read, and images a sandbox run produced. Every image, from your machine or from the web, is first rebuilt inside the gVisor sandbox with no network: PNG, JPEG, GIF and WebP are accepted, SVG is refused, metadata is removed, and size, pixel and frame limits apply. The page only ever loads the rebuilt copy from Aman itself, never an image from another site.

Images from the web ask first:

- **Images in an email** always show a card, one per email: "Show 3 images from this email? The sender's servers will see that the email was opened."
- **An image link in a reply** loads without asking only where a web search would (the link came back from this turn's searches and searches run without asking). Otherwise a card asks: "Show this image from example.org? That site will see that you looked at it."

Every download goes through the same outbound checks and audit log as web search. Rebuilt images are kept per user for 30 days, at most 256 MB each, and are deleted with the chat.

Images need the gVisor sandbox. A normal [installer](/install) install has it. An install made with `--no-sandbox`, or a server that runs code in plain Docker instead of the gVisor sandbox, shows "Image checks need the sandbox, which is off." in place of each picture.

## Links, and pictures outside a chat answer

Links in an answer, or on any page the app renders from markdown, ask before they open a site outside this app. The dialog shows the full address first. Tick "Don't ask again" for that site and links to it open straight away after that; the choice is kept on this device only. Links to this app itself open as before, without asking.

A picture from another site outside a chat answer is not loaded until you choose **Show image** and confirm, because the site will see that you looked at it. "Don't ask again" works there too, per site: a site you trusted loads its pictures on its own from then on. Pictures inside a chat answer follow the rebuild flow above instead.
