This page explains what Aman keeps from the Personalization page and how it uses it. To fill in the page, see [Personalization](../packages/trueforge/guide/topics/personalization.md).

## What is stored

Personalization is one profile per signed-in person. It holds only:

- your name, and how the assistant should address you
- the assistant's name and a short identity
- voice guidance
- a short profile of you
- up to 12 pinned preferences, each up to 280 characters
- the areas you picked for the Tour's "What would help you most?" question, in the order you picked them; they shape the Tour's cards and are never sent to the model
- an optional learned profile, kept up to date by Aman when profile learning is on
- the profile learning switch, off by default

Each text box holds up to 2,000 characters. Everything you write, apart from the learned profile, adds up to at most 5,500 characters. The learned profile has its own limit of 4,000.

The profile is stored in Aman's database on your computer: SQLite in standalone mode and Postgres in distributed mode. It is never filled in from chat history on its own, and it is never shared with other people who use the same Aman.

??? note "What the profile records about itself"

    The profile records its owner, who last changed it, timestamps, a revision number that only goes up, and a SHA-256 digest of the parts the model sees.

    Saving identical content leaves the revision unchanged. The learning switch and the help areas are not shown to the model, so they are outside the digest. The server compares them separately, so changing either one alone still saves and still advances the revision.

## What the model sees

On every main-assistant turn, the server builds one size-limited `<personalization-context>` section from the profile. Helpers that Aman starts for a task (subagents) never receive it.

When the main assistant answers, the section holds:

- the assistant's name, identity and voice
- your name and how to address you
- your profile, pinned preferences and learned profile

When a [persona](../packages/trueforge/guide/topics/personas.md) answers, the persona is the only assistant identity. The server leaves out the main assistant's name, identity and voice. It keeps your name, how to address you, your profile, pinned preferences and learned profile.

The persona and its instructions stay visible in **Roles and Personas** and on the chat's "who is answering" button.

## Learned profile

Profile learning is off until you turn on **Learn from conversations** in **Settings**, **Memory**, on the **Learned profile** tab. The switch is saved with the rest of the profile as `learning_enabled`. Someone with no profile has never opted in, so nothing runs for them. There is no server-wide switch and no restart needed.

### What it does

With learning on, Aman runs a short pass after each finished turn.

1. A model call reads the current learned profile and that turn's exchange.
2. It returns the whole profile rewritten: lasting facts, preferences and ways of working, under Markdown headings.
3. If the exchange held nothing lasting, the profile comes back unchanged and nothing is written.

The pass checks the switch as it starts and again after the model call. If you turn learning off during a turn, the pass stops without writing anything.

### Limits

- The pass never delays or fails the turn it learns from. If anything goes wrong inside it, it quietly does nothing.
- After the pass writes, it waits before writing again: `PROFILE_LEARNING_MIN_INTERVAL_MS`, one hour by default. Your own edits are never limited.
- `PROFILE_LEARNING_MODEL` picks a separate model for the pass. When it is empty, the pass uses the turn's own model. Neither setting turns learning on.

### The change trail

Every write by the pass adds an `aman.profile.learned` event to that turn's event log. The event holds the previous profile, the new one, and the new revision number, so you can review every change through the events API. With **Agent details** on, the answer also shows a **Learned profile updated** card.

When a memory provider is set up, a pass that finishes with learning still on also copies the current profile into it, under one document id per person. An unchanged profile is not stored twice.

### Where you see it

The learned profile goes into the `<personalization-context>` section after your pinned preferences, with a note saying it was learned from past conversations. You can read, edit or clear it at any time in **Settings**, **Memory**, on the **Learned profile** tab. What the model sees is exactly what that tab shows. **Clear all** on the Personalization page empties only that page's fields and keeps the learned profile, its switch, and your Tour help areas.

## API

```text
GET    /api/v1/personalization/profile
PUT    /api/v1/personalization/profile
DELETE /api/v1/personalization/profile
GET    /api/v1/personalization/context
```

- The signed-in identity owns the profile. A caller can't pick another person's profile.
- `PUT` replaces the whole profile. A `PUT` with nothing in it is refused, because `DELETE` is how you remove a profile.
- `learning_enabled` counts as content whether it is on or off. So a profile holding only the switch is valid; that is where someone lands after trying profile learning and turning it back off. Leaving the field out counts as no content, and as learning off.
- `GET /api/v1/personalization/context` returns the main assistant's view of the profile. On a persona turn the server builds the persona's view from the persona settings.
- `profile_digest` identifies the source profile, not the exact text sent to the model.

## Not included yet

Personalization doesn't pull separate memories out of chats, build search indexes, or store hidden reasoning. The learned profile is its only automatic write. It is off by default and always fully visible.
