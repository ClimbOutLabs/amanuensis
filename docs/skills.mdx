A skill teaches an agent how to do a particular job, such as querying a database, sorting an alert, following an escalation playbook or drafting release notes. To turn skills on and use them, see [Skills](../packages/trueforge/guide/topics/skills.md).

A skill is a folder in a git repository with a `SKILL.md` file at its top. You add skills once in **Settings → Skills**. Then you switch them on for a chat, or attach them by name when you [create an agent](create-agent/overview.mdx).

## Adding a skill

Open **Settings → Skills**. Either enable a starter skill from the catalog, or click **Import from GitHub** and give the repository URL, the folder that holds `SKILL.md`, and the branch.

!!! tip

    For a setup you rely on, pin a tag or a commit instead of a moving branch, so the skill doesn't change under you.

The starter skills come from the skill catalog that ships with Aman. See [Initial setup](harness/initial-setup.mdx#what-is-supported-out-of-the-box) for how catalogs work and how to change what Settings offers.

## What a skill contains

```text
customer-support-skill/
├── SKILL.md
├── references/
│   └── escalation-policy.md
└── scripts/
    └── classify_ticket.py
```

`SKILL.md` starts with YAML front matter (`name` and `description`), followed by Markdown instructions.

The agent sees only the `description` at first. It loads the full instructions and the supporting files only when it picks the skill. This is called progressive disclosure, and it keeps unused skills from taking up room in the conversation.

## What a skill needs to run

!!! note

    Skills need the agent's [sandbox](sandbox.mdx) to be on. The skill's repository is copied into the sandbox, and the agent reads `SKILL.md` and runs any bundled scripts there. Two skills on one agent can't share the same name.

While a turn runs:

1. Aman shows the model each attached skill's name and description.
2. When the model decides a skill fits, the repository is copied to `/opt/tfy/skills/{name}` in the sandbox.
3. The agent follows `SKILL.md` and uses the supporting files as needed.

### Network access

A skill has no internet access by default. A skill can list the sites it needs. Settings then asks the person to allow them, and once allowed, a chat using that skill can reach those sites and no others. Settings warns when one of the sites can send email.

## Skills and connectors

- Skills say how to handle a task: the steps, the decisions and the format.
- Connectors (MCP tools) provide the actions and the data.

For example, a customer follow-up skill sets the tone and when to escalate. Connectors look up the record, update the ticket and post to Slack.

## Tips for writing a skill

- Keep the `description` sharp. It is the only thing the model sees before it loads the skill.
- Write `SKILL.md` like instructions to a capable teammate.
- Put long reference material in supporting files that the skill links to.
- Prefer several focused skills to one sprawling one.
