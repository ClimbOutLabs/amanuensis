The terminal app puts Aman in the terminal on your computer. You pair it once with a one-time code, and after that you can read and write your chats from the command line. Replies stream in as they are written, the way they do in the web app.

The terminal app is a separate program from the web app. It talks to the same Aman, on the same computer or on your own network, and it sees the same chats.

## Install the terminal app

The terminal app needs Node 22.14 or newer, the same as the rest of Aman.

Run it without installing it:

```bash
npx @truefoundry/aman-tui
```

Or install it, which puts the `aman-tui` command on your path:

```bash
npm install -g @truefoundry/aman-tui
```

Every command on this page is written as `aman-tui`. When you run it through npx instead, put `npx @truefoundry/aman-tui` in its place. Run `aman-tui help` to list the commands.

## How pairing works

Pairing gives one terminal its own key to one Aman. The key stands in for you only on the chat side of Aman. It cannot open settings or anything else that belongs to the owner alone.

A pairing starts from the terminal, and you confirm it in the web app, signed in as yourself. That way a key is only ever handed out after you have seen the code on both sides.

The code is eight characters. It works once, and it lasts five minutes. A wrong, expired, or already used code is refused with one plain line, and you start pairing again.

## Pair a terminal

1. In the terminal, run `aman-tui login <address>`, with the address Aman is opened at. For example, `aman-tui login https://my-computer.example:8443`. The terminal is paired under your computer's name. Add `--name <name>` to pair it under a name of your choosing, which is the name you will see later in Settings.
2. The terminal shows the code in large clear text, and a link.
3. Open the link in the web app. Check that the code on the page matches the code in the terminal, then confirm.
4. The terminal receives its key and saves it. Run `aman-tui` to start chatting.

If the address is not one Aman is set up for, the terminal shows Aman's own answer, word for word, including the one thing to run to fix it.

## Where the key is kept

The app keeps its own small files in one folder. On a Mac and on Linux, that is the `aman-tui` folder inside `.config` in your home folder, or inside the folder XDG_CONFIG_HOME names when that is set. On Windows, it is the `aman-tui` folder inside your AppData roaming folder. On a Mac and on Linux, the folder and the files in it are set so only your account can read them. On Windows they rest on the AppData folder itself, which Windows keeps private to your account.

On a Mac, the key itself is kept in your login keychain. On Linux, it is kept in the desktop secret service when one is running. Everywhere else, which means Windows and a Linux computer with no secret service running, the key is kept in a file in that folder, with no lock of its own on Windows beyond the folder it sits in. The key is never printed and never shown.

One honest limit on a Mac. The keychain tool that comes with the system takes the key as part of its command, so while the key is being saved, another program running under your account that lists running program commands could see it. Saving takes less than a second, and the key is not visible at any other time. This version accepts that limit.

You can pair the same terminal with more than one Aman. Run `aman-tui login` again with the other address. Each one keeps its own key and its own name. Run `aman-tui instances` to list them, `aman-tui use <address>` to choose which one opens, or switch inside the app.

To take a terminal's key away, open Settings in the web app and revoke it under Paired terminals. The terminal is refused from its next request on. Changing your password on an Aman that uses its own sign-in also takes away every terminal key at once. On an Aman that uses a sign-in service, there is no Aman password to change, so revoke the key in Settings instead.

## Chat from the terminal

Run `aman-tui` with no command. Running `aman-tui chat` does the same thing. Your chats are listed newest first, with the persona and when each was last active. Pick one to open it, or start a new chat. The keys on this screen work in either case, so a capital Q leaves just as a small one does.

Inside a chat, type your message and press Enter. The reply streams in as it is written. If the connection drops in the middle of a reply, the terminal says the connection was lost and rejoins the same turn the way the web app does, and the reply carries on. Press R while it rejoins to retry at once.

Press Esc while a reply is streaming to stop it. The part of the reply that already arrived stays on screen, with a line saying the reply was stopped.

Tool calls appear in the flow as plain cards. Each card names the tool in plain words, shows what it is doing, and shows how it ended. A picture or a file in a chat cannot be shown in a terminal, so a line appears in its place offering the chat's web address to open in a browser.

## Approvals in the terminal

Some actions wait for your OK before they run. When that happens, the terminal shows the whole action before you can answer it. For an email, that is the account it sends from, who it goes to, the subject, the whole message, and the files sent with it. Nothing is cut to fit the window. Scroll with the up and down arrow keys to read all of it before you answer.

Press A to allow it once. When the action offers it, press Shift+A to always allow it everywhere. Press D to say no. The words on the no choice say what will not happen, such as Don't send. Enter never approves anything. Enter is how you send a chat message, so approving takes its own keys.

An email is always a draft first, and sending it is a separate approval, exactly as in the web app. The terminal never puts the two together. If the action was already answered somewhere else, or the chat has moved on, or the request has ended, the terminal says so in plain words and nothing more is done. An action a scheduled run held for you is answered in the same way.

## Ask one question and exit

Run `aman-tui "your question"` to ask one question on the active instance. The answer is printed, and the command exits. The exit code is zero only when an answer printed.

A one-shot question never approves anything. When the turn ends waiting for an approval, the command says the answer is waiting and points you to the terminal app or the web app, and it exits without answering the approval.

## When something goes wrong

**The terminal says Aman no longer accepts this terminal's key.** The key was revoked in Settings, or every key was taken away by a password change. Pair again with `aman-tui login <address>`, using the address the line names. Nothing in the terminal can fix a refused key, and trying again will not help until you pair again.

**The terminal says the key is not on this computer any more.** The keychain entry or the key file is gone, for example because the keychain was cleared. Pair again with the login command the line names.

**Pairing is refused at the address.** The terminal shows Aman's own answer word for word. When the address is not one Aman is set up for, that answer names the one command to run to fix it.

**A one-shot question ends without an answer.** When the turn is waiting for an approval, the command says so and points you to the terminal app and the web app. Answer the approval in one of those, then ask again if you still need the answer.

## What this version does not do yet

This version has no settings, no connectors or skills screens, no schedules screen, and no way to edit memory. Pictures are not shown inline. On an approval there is no change-it answer and no way to pick a different sending account. Say no and ask again in chat instead.
