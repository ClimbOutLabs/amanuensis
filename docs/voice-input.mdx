The chat composer has a microphone button beside Send. Tap it to start recording, tap it again to stop: the recording is transcribed locally and the text is inserted into the composer, where it stays editable before sending. Typed input keeps working exactly as before, whether or not transcription is available.

Transcription runs fully on your own hardware. The browser encodes the recording as 16 kHz mono WAV and posts it to the agent server (`POST /api/v1/voice/transcribe`); the server forwards the bytes to the `aman-stt` sidecar, which runs Whisper `small` (int8, CPU) via faster-whisper and returns the transcript. The browser never talks to the sidecar directly, and no audio or transcript ever leaves your machine. When the sidecar is unreachable, the mic button shows as unavailable and everything else keeps working.

## Ways to talk

- **Tap to record.** Tap the mic, talk, and tap it again. Your words go into the message box so you can check them before you send.
- **Hold to talk.** Hold the mic, talk, and let go. Your words are sent as soon as they are written down.
- **Hold-to-talk keys.** On a computer, hold Ctrl + Shift + Space while you talk, and let go to send. You can pick other keys, or turn them off, in Personalization under "Talking to Aman". The choice is saved in this browser only.
- **Hands-free.** Tap the hands-free button beside the mic. Aman listens, sends what you said when you pause, reads the answer aloud, and then listens again. Tap the button again to stop. Hands-free also stops when you switch chats, leave the page, take the mic by hand, or stay quiet for 30 seconds. It is never on unless you turn it on, and it only listens in the chat where you turned it on.
- **Paste.** Choose "Paste from clipboard" in the `+` menu to add copied text to your message. To copy an answer, use the copy button under it.

## Where your voice goes

This section is the voice feature's data-flow record.

- **Your voice.** The browser records only while the mic is on: while you record, hold, or have hands-free on. The recording goes to the Aman server on your computer, which passes it to `aman-stt` and gets the words back. The recording is not saved.
- **The answer read aloud.** The answer's text goes to the Aman server, which passes it to `aman-tts` and sends the audio back. When `aman-tts` is not running, your browser's built-in voice reads it instead, and the text stays in the browser.
- **What never leaves your computer.** Your recordings, the words written down from them, and the audio of the answers. No speech service on the internet is called.
- **What is kept.** Only the messages themselves, like any typed message. The server logs sizes, timings and status codes, never what was said.

## Deployment

`docker-compose.yml` runs `aman-stt` as a sidecar next to the server:

- Built from `ops/aman-stt` (Python 3.11 slim, CPU-only; the image has no CUDA userspace and the app pins `device=cpu`).
- Pinned to cores `16-19` with a 2 GB memory limit, so transcription work never contends with chat or embedding work, which stay on cores `0-15`.
- No host port is published; the sidecar is reachable only inside the compose network at `http://aman-stt:8001`.
- The Whisper model (~464 MB) downloads once at first startup into the persistent `stt-model-cache` volume; container recreates reuse it.
- `restart: unless-stopped`, matching the server.

The server reads the sidecar address from `STT_URL` (default `http://aman-stt:8001`; compose sets it explicitly). The server does not wait for the sidecar to be healthy before starting: typed chat stays available when transcription is down.

## Host development

`pnpm dev:infra` starts `aman-stt` from `docker-compose.dev.yml` next to Postgres and Redis, while the server and UI run on the host with `pnpm dev`. The service uses the same build, image, memory limit and thread count as the full stack, with two differences: it publishes `127.0.0.1:8001` (loopback only, since the sidecar has no authentication) and it has no `cpuset` pin, because the host-run server cannot be pinned to a disjoint core set and a fixed range would fail on hosts with fewer than 20 cores. The first `pnpm dev:infra` builds the image and downloads the model (~464 MB) into the dev project's own `stt-model-cache` volume, separate from the full stack's.

Point the server at the published port by setting `STT_URL=http://localhost:8001` in `packages/trueforge/.env` (already present in `packages/trueforge/.env.example`), then restart `pnpm dev`. Without it the server looks for `http://aman-stt:8001`, which only resolves inside the compose network, and the mic button stays hidden.

## Tuning

**Fewer or more CPU cores.** The `16-19` / `0-15` split assumes a 20-core host. On a host with a different core count, move both pins together and keep them disjoint: give the sidecar 4 cores and the server the rest. For example, on a 12-core host, pin `aman-stt` to `8-11` and the server to `0-7`. The server pin lives on the `server` service (`cpuset`), the sidecar pin on `aman-stt`.

**Transcription threads.** `AMAN_STT_CPU_THREADS` (default `4`) sets the Whisper encoder thread count; keep it equal to the number of cores pinned to the sidecar.

**Model size.** `AMAN_STT_MODEL` (default `small`) selects the Whisper model; `AMAN_STT_FALLBACK_MODEL` (default `base`) is used when the primary fails to load. Larger models transcribe more accurately and need more RAM; raise the service `mem_limit` accordingly.

**Memory.** The default 2 GB limit covers the `small` int8 model with headroom. If the container is OOM-killed during warmup, raise `mem_limit` before changing anything else.

**Request limits.** The sidecar caps audio bodies at 30 MB (`AMAN_STT_MAX_BODY_BYTES`); the server caps them at 6.4 MB, which is 200 seconds of 16 kHz mono 16-bit audio, enforcing the 3 minute recording cap server-side. The browser also caps recordings at 3 minutes client-side. Transcription requests time out after 120 seconds server-side.

## Spoken replies: the voice on your computer

Replies can be read aloud. When the voice container is running, replies are read by a voice that runs on your own computer. When it is not, your browser's built-in voice reads them instead.

**Choosing the voice.** Pick one of six voices in Personalization under "Voice replies". Heart is the default. Picking a voice plays a short sample. The choice is saved in this browser only.

**What it is.** A small container called `aman-tts`. It runs the Kokoro voice model (Apache-2.0) on the computer's processor and turns reply text into audio. The model and its voices are built into the container, so it never goes online.

**Nothing leaves your computer.** The browser sends the reply text to the server, which passes it to `aman-tts` and sends the audio back. The text and the audio stay on your computer, and neither is saved or written to the logs.

**Limits.** One request reads at most 4,000 characters, and each person can ask for 30 readings a minute. Longer replies are read in parts.

**How to turn it off.** Stop the container, and replies are read by your browser's voice instead:

- Installed with the installer: run `docker stop aman-tts`. It starts again the next time the installer or `aman upgrade` runs.
- With `docker-compose.yml`: run `docker compose stop aman-tts`.
- With `pnpm dev:infra`: remove the `aman-tts` service from `docker-compose.dev.yml`, or stop it with `docker compose -f docker-compose.dev.yml stop aman-tts`.

For host development, set `TTS_URL=http://localhost:8002` in `packages/trueforge/.env` (already in `packages/trueforge/.env.example`). The server reads the address from `TTS_URL`, which defaults to `http://aman-tts:8002`.
