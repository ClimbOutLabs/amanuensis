# Memory

## How memory works, in plain words

Aman remembers things between conversations so you don't have to repeat yourself. Here is the plain-English version of how that works — the technical details live in [How it is stored and recalled](#how-it-is-stored-and-recalled) below.

**Memories are ordinary files.** Aman saves what matters from your conversations as plain text files (Markdown) on the server, in its memory folder (by default, `./data/memory` next to the server). There is no database to manage and nothing locked away: the files are human-readable, and they're yours.

**After each chat, only the lasting facts are saved.** Instead of keeping every turn word for word, the assistant picks out facts about you, plans, preferences, decisions, and anything you asked it to remember, and saves those. A turn with nothing lasting saves nothing. Each fact is a short note that starts with what it is about, such as "Sister Lexie is allergic to shellfish", without your name in front. Aman uses your name only where a note would be unclear without it. Notes saved before this change keep their wording. If a summary can't be made for a turn, nothing is saved for that turn, and the Memories page tells you. If you'd rather keep every turn word for word, turn the **Turn summaries** switch off in **Settings → Memory**; new turns are then saved word for word. Each turn is then saved as two notes. Your words are one note. Aman's reply is a second note, marked `> External source: assistant reply`, so what Aman said is never saved as something you said.

**What Aman learns about you lives in your profile, not in memory.** The learned profile lives in **Settings → Personalization** and is added to every reply from there. It has a size limit. When it is full, its oldest fact about you is moved into memory, word for word, to make room for the new one, so nothing is lost and there is nothing for you to tidy. Earlier versions also saved a copy of it as a note in memory. When you clear the learned profile or delete your profile, Aman stops using that copy at once, it no longer shows in your memories, and its text is removed from your disk like any memory you delete.

**Aman finds memories by meaning, not just words.** When you ask something, Aman searches your memories for meaning — so "where did we stay in Paris" finds the hotel note even though it says "Hotel Lumiere" and never mentions Paris. To do that, the first time Aman runs it downloads a small helper model once (about 120 MB), automatically in the background: the download starts when the server starts, so it's usually finished before you need it. There is nothing to install and nothing to click. After that one download, memory search works fully offline, and everything stays on this server. If the download can't finish, Aman just keeps finding memories with keywords, and keeps retrying in the background.

**A note is shown only when your message is clearly about it.** Aman looks through every saved note, from the whole log and not only the last two weeks, and compares what each note means with what you wrote. It shows a note only when your message is clearly about it. A message that only shares a word with a note, such as "remember", shows nothing. Aman shows at most four notes for one message, or six when no page holds any fact yet. A note that Aman has already sorted onto a page is left out of this search, because the page already holds it and keeps track of what has changed. Your own words that Aman found no page for stay in the search. When very little is saved, fewer than five notes and facts together, Aman cannot tell what is clearly about something, so it finds notes by shared words as well. It does the same while the helper model is not ready.

**Messages you send.** When you send an email through Aman, it keeps one note of it in the daily log: who it went to, the subject and what you wrote. Aman does not ask a model to write this note, so it is saved even when turn summaries are off. If you forward a message, only the words you added are kept, never the message you forwarded. A draft is not kept, and neither is a message that did not go out or whose delivery was uncertain. A message you send from an incognito chat is not kept either. A very long message is cut, and the note says so. Each note closes with `> External source: a message you sent`, and the Memories page shows those words. Notes an older version saved with `> Source: a message you sent` show the same new words. [Memory design](../ops/memory/DESIGN.md#messages-the-person-sends) has the details.

**Pages about the people and matters in your life.** Beside the saved notes, the memory folder can hold short pages, such as `people/wendy.md` or `matters/lisbon-trip.md`. A page's file name must be the lowercase name, so rename a file such as `Wendy.md` to `wendy.md` or Aman will not read it; the server log warns when a file is skipped for this reason. When your message names someone who has a page, Aman reads that page first, so it starts the reply already knowing the basics. A name in one of your earlier messages in the same chat counts too, so "What can she not eat?" finds the page for the person you named a moment ago. Aman can also find a single fact on a page by its meaning: "Who lives next door to us?" finds "Aiko Tanaka is the neighbour at number 14" even though the page is not named. It shows up to six such facts, each under its page, and shows nothing when your message has nothing to do with what it remembers. A fact that has ended is shown as earlier, and only for a month unless you ask about the past, for example with "used to". Finding facts by meaning needs the helper model; until it is ready, Aman reads only the pages you name. Each fact on a page is one line, and a hidden note on that line records where it came from: something you said, something you wrote by hand, or something read in mail. Only your own words count as instructions for how to write to a person. Aman does not list your pages in every reply. When you ask about something and no page was shown for it, such as "What am I waiting on?", Aman can look at the list of pages and open one that looks relevant. It shows the same lines, with the same labels, as when your message names a page. A page that holds a line Aman read is treated like any page shown to it: in that reply Aman changes or forgets a line of your own only when your message names that line. Pages with no line of your own are listed apart, and their name is marked as not confirmed by you, because a model chose it from something it read. None of this happens in an incognito chat. You can write pages by hand. You can also tell Aman in a chat to remember, change or forget a fact about someone, and it keeps that on their page. What you type in that message is saved as yours, marked `From you`. You can also ask Aman to save something it read for you, such as an address from an email, with "Save that". Aman saves it on the page straight away, with no extra step, and marks the line `External source: read content`. It makes a new page if there is none yet. Aman does not save a line that looks like a password, a key or a card number onto a page, even when you ask. It tells you it did not save it. A line marked this way is never treated as your instruction, and it never replaces a line of your own: when the two differ, Aman keeps both. To replace your own line, say the new fact yourself. How you like to write to someone is saved only from your own words. In a reply where Aman has read mail, the web or a file, it changes or forgets a line of your own only when your message names that line, as in "forget that Wendy plays tennis". A link or email address in a memory that came from something Aman read, such as a mail, a web page or a file, still counts as something Aman read whenever it is recalled in a later chat, so Aman may check with you before it sends something to it. Each change Aman makes is kept in a history next to your pages, so it can be undone. Your own edits are noted the next time Aman writes. Pages travel with an export and come back on import, so moving to a new computer does not lose them. Pages work with the default Markdown memory only. [Memory design](../ops/memory/DESIGN.md#pages) has the details.

**Seeing and fixing your pages.** Open **Settings → Memory → Pages** to read the pages Aman keeps. People and matters are in two groups, and you can search by a name or another name for the page. Each row in the list shows the name, a short summary and the day the page last changed. Aman writes the summary when it makes a page: one line on what the page covers and when it is worth reading. It is a description for you only. Aman is never shown it as something you said. Open a page to see the summary and then its facts, one short line each. Each line that is not yours says `External source:` and then where it came from, such as email, calendar, read content or a message you sent. A line of your own says `From you`. Lines under Unconfirmed say they are not confirmed, and you can **Confirm** or **Dismiss** each one. A confirmed line becomes yours. You can also edit a page as text. If the page changed while you were editing, Aman asks you to reload it and try again. **Delete** removes a page, and for a few seconds you can undo it. Under each page you have **Copy**, **Edit** and **Delete**, the same as under a memory. Every change to a page is kept in a history next to your pages on disk. This tab shows only with the default Markdown memory.

**Sorting what Aman saves onto pages.** Aman can sort each note it saves onto your pages: a new fact goes on the right page, a changed fact moves the old one to Earlier, and a fact that is already there is only marked as seen again. This is off until you turn it on. Open **Settings → Memory** and find **Sort what Aman saves onto pages**. Choose **Off**, **Only note what it would do** or **On**. The change counts from the next note Aman saves, with no restart. It uses the model while you are not chatting. With **Only note what it would do**, Aman writes the plan to a file called `.sorter-report.jsonl` in the memory folder and changes no page. The report holds the plan in Aman's own short words, never the note itself. When you delete or edit a memory, what Aman planned for it leaves the report too. With **On**, Aman writes the pages, but we advise waiting until it has passed our tests. A server can set the starting choice with `MEMORY_PAGE_SORTING` (`off`, `report` or `on`, default `off`). What you choose in Settings wins over it. The controls show only with the default Markdown memory. Aman treats your own words and what it read differently. A fact from your own words can be confirmed. A fact from mail, the web, a file or Aman's own reply is only ever added as unconfirmed. Aman never changes, ends or removes something you confirmed because of what it read, and never writes how you write to someone from it. Nothing is sorted in an incognito chat.

**A small tidy once a night.** This is off until you turn it on. Open **Settings → Memory** and switch on **Tidy pages once a day**. The change counts from the next time Aman looks at the clock, with no restart. Once a day, in the quiet hours of the server's day, Aman then tidies your pages, and it uses the model while you are not chatting. It does three things. It moves a line to Earlier when the end day you or Aman gave it has passed. It sorts notes from the last 14 days that were missed, as far as your sorting choice allows. With sorting off, it skips this and the next step. It looks for two lines on a page that cannot both be true, and lists them for you. On the page you see "These lines disagree" with both lines and a reason. Edit the page to fix the line that is wrong, or choose **Not a problem** and Aman will not list that pair again. Aman never changes the words of a line, never removes a line, and never decides which of two lines is right. It does the same for each persona's pages. To turn the tidy off, switch **Tidy pages once a day** off. A server can set the starting choice with `MEMORY_NIGHTLY_JOB` (`true` or `false`, default `false`). What you choose in Settings wins over it. It needs the same model as your memory notes, so it does nothing in those steps when no model is set up. Nothing is tidied because of an incognito chat.

**Old memories stay findable.** Aman looks through everything it has saved, however long ago. One kind of note is different. Notes that Aman took from something it read for you, such as an email or a web page, are brought up for 14 days. After that they stay in your files, but Aman no longer brings them up on its own.

**Keep the memory folder safe.** The downloaded helper model lives inside the memory folder too, so they travel together. If you run Aman with Docker, make sure the memory folder is stored on a persistent volume: without one, your memories — and the downloaded model — disappear whenever the container is recreated.

## How it is stored and recalled

Memory is on by default. Amanuensis recalls from local Markdown files before every reply and retains what matters from each completed turn, so the model never has to remember to use it. Memories live as plain files under `MEMORY_MARKDOWN_DIR` (default `./data/memory`, relative to the server's working directory) — human-readable, portable, and yours. In Docker, mount a volume at that path so memories survive container recreates.

An incognito chat reads memory but never writes to it. Aman recalls from the vaults as usual, but saves nothing from the chat, in any persona, and the chat never joins past-chat search. See [Privacy](/privacy#incognito-chats).

Memories are scoped by persona. While a persona is active, what it learns is kept in that persona's own vault and is private to it until you share the vault. With no persona active, memories go to the shared vault, which every persona can read. A persona recalls from its own vault, the shared vault, and any vault shared with it. Renaming or deleting a persona never deletes its vault.

When you delete a memory on the Memories page, Aman removes its text from your disk. When you edit one, the old wording is replaced by the new wording. A backup or an export you made earlier still holds what it held, so delete those too if you want the words gone from them.

### Where each note came from

Every note ends with one line that says where it came from.

- `> From you` means you said it in a chat.
- `> External source: ...` means it came from somewhere else. The line names the source: `email`, `calendar`, `web page`, `attachment`, `tool result`, `assistant reply`, `a message you sent`, `read content` or `imported file`.
- `> External source: assistant reply, nothing read before it` is a note of Aman's own reply from a chat where Aman had read nothing from outside up to that reply: no email, page, file, tool result or external memory. Aman treats it as its own earlier reply and not as other people's content. An email address in it still counts as something Aman read. If you edit the note, it becomes a plain `assistant reply` note.

Aman treats a note as your own words only when it ends with `> From you`. Everything else counts as something Aman read. Aman still remembers it, but it asks you before it uses a link or an address from it. See [Safety](/safety).

Aman never guesses a source. A note that would be saved without one is not saved at all. A note with no source line counts as external.

- **Notes saved before this.** The first time this version starts, Aman adds a line to every older note that has none. The line is `> External source: no record`, because nothing shows where those notes came from. Each daily file is copied to a `.before-source-lines` folder in its vault before it is changed. Aman does this one vault at a time, while it holds that vault's lock, so a note saved at the same moment is not lost. A note you deleted stays erased and is not given a line. To make a fact your own again, say it to Aman in a chat, or review your older notes once (see below).
- **Reviewing older notes.** Some older notes were saved in a chat where Aman had read nothing from outside and you had attached no file. The Memories page shows a notice for these, with a **Review older notes** button. The list shows each note with its day, its text and the title of its chat. Nothing is ticked at the start. Tick the notes that are your own words, then click **Mark the ticked notes as from me**. Aman treats those notes as your own words from then on, and acts on them without asking, as it does for things it read. A note is left out of the list when its chat read something from outside, when you attached a file in that chat, when its chat is gone, or when you edited or forgot the note. A note you mark is not rewritten. Aman records your choice in a `.reviewed-from-you` file in the vault and shows the note as `> From you` while its text stays the same. If you edit the note later, it still counts as from you. A full export carries that file, so a restore keeps your review.
- **Imports.** Notes you bring in with the Memories import are saved as `> External source: imported file`. When you import a full export made by an older version, its notes get the same line as older notes. You can review them too, if their chats came over in the same import.
- **`MEMORY.md`.** A `MEMORY.md` file you write by hand counts as external unless its last line is `> From you`.
- **Editing and deleting.** Changing a note on the Memories page changes what it says. It never changes where it came from. A note you reviewed as your own still says `> From you` after you edit it, in the list, in recall and in the file. A note from somewhere else cannot become yours by editing it. A deleted note is erased from the file, and a review you made of it has no effect on any other note.
- **Other memory services.** With a memory service other than Markdown files, a memory with no recorded source counts as external too.

## Searching past chats

Aman can also look through your earlier chats when you ask, for example "what did we decide about the trip?". This is off until you turn on past-chat search in Settings. While it is off, nothing from your chats is added to the search. When you turn it on, Aman adds your earlier chats in the background, then adds each new chat as it finishes. When you turn it off, everything it added is removed.

The search follows the same rule as memory. A persona finds its own chats, chats with the main assistant, and chats of personas whose vault is shared with it. A chat with a persona whose vault is not shared stays out of the search.

You can also search the words inside your chats yourself. Open the search box at the top of the Chats list and type. Chats whose titles match come first, and below them, under "In messages", come chats where a message holds your words, each with a short piece of that message. Click one to open it. This search covers all of your own chats, whichever persona answered, because you can already open every chat in your list. It needs the same switch: while past-chat search is off, the box matches titles only.

A message matches when it contains every word you searched for, as a whole word. Small filler words such as "the" are ignored, and "trip", "trips" and "tripped" count as the same word, while different words such as "made" and "mad" stay apart.

Manage it in **Settings → Memory**: see what's stored, turn recall on or off (the rail toggle does the same), and check the memory status. Recall is bounded, so a large memory can't blow up the model's context window, and every recall is auditable.

Two optional Prompt Guard screens can check content around memory before it reaches the model, both off by default:

- **Memory recall screen**: screens recalled memories before they reach the model. Turn it on in Settings → Memory with the "Screen recalled memories with Prompt Guard" switch; it needs a classifier URL configured and reachable first. Your own stated memories are never withheld; it only applies to memories that came from tools, documents, or email.
- **Tool output screen**: screens tool results before they re-enter model context. This one is environment-only, with no Settings switch, and shares the same classifier URL, token, and threshold as the recall screen.

See [Deployment Security](deployment-security.mdx#prompt-guard-screens) for the full configuration and [Memory design](../ops/memory/DESIGN.md) for how recall and retention work.
